Limits, stated on purpose: the hook sees the command line before the Bash call starts; a command that changes files before its `git commit` is not seen. The hook does not follow `cd`, resolve Git aliases or read scripts. A word `git` after another program (`echo git commit`) counts as a call. The count is of syntactic occurrences, not of executions. The walk finds the end of a `$(...)` substitution by counting parentheses and takes no account of quotes or heredocs: a parenthesis inside a quoted word or a heredoc body can end a substitution early or leave a text that cannot be split. The key `parse` records such lines; it does not repair them. A split that succeeds does not show that the shell reads the line the same way. The lines with `parse` `failed` count candidates that match the pattern of D3, false positives included; they are not the rate of failure over all real commits. The tokens do not show whether a digit touched a redirection operator or stood in quotes, so `-m 2 >F` loses its value word. The budget is cooperative: it does not bound a blocking file-system call or the total time of the hook. The records and the observation file are local and untrusted. The observation describes; it decides nothing. Definitions
D1. When it runs. The guard's deny decision runs first, with the code that exists at `2929b899585092be2da505cd739d272336d919bb`. The observation runs only when all of these hold: the event is a Bash call with a string command; the guard does not deny it; the environment variable `READBACK_COMMIT_CHECK` is not exactly `off`; the command line holds a commit call or is a failed-parse candidate (D3). In every other case the hook imports neither `commit_observation` nor `review_capture` and writes nothing.
D2. Walk. `hooks/guard_git.py` gets one function that returns the simple commands of a command line as word lists. It visits each `$(...)` and backtick substitution first, innermost first, then the line. The body of a visited substitution is removed from the text that encloses it before that text is split, to avoid counting a recognized Git occurrence twice. The words after `eval` and the `-c` string of a shell (`bash`, `sh`, `zsh`, `dash`, `ksh`) are walked in the place where they stand. A text that `shlex` cannot split gives no simple command. A word of digits only that stands directly before an operator token whose first character is `<` or `>` is a file descriptor and is not a word of the simple command. The walk also reports whether every text that it visited was split.
D3. Commit call. A simple command in which a word whose last path part is `git` is followed, after Git's global options, by the word `commit`. Global options with a value are those of `GIT_OPTIONS_WITH_VALUE`. The first commit call in walk order is described; `commit_count` is the number of commit calls in the line. `parse` is `ok` when a commit call is found and every visited text was split; `partial` when a commit call is found and a visited text could not be split; `failed` when no commit call is found, a visited text could not be split, and the raw command matches `\bgit\b[^;&|\n]*?\bcommit\b` (a failed-parse candidate). For `partial` the first recognized commit call is described and `commit_count` is the number of recognized calls, which can be incomplete. For `failed`, `commit` and `commit_count` are null, `target` is `unknown`, the fields of D8 for an unknown target apply and no capture is taken, and the event's `cwd` when it is a string, else `.`, is the storage base only. A line without a commit call that is not a failed-parse candidate gets no line.
D4. Base folder. The event's `cwd` when it is a string, else `.`; each global `-C <path>` of the described commit call is joined to it in order.
D5. For a recognized commit call, `target` is `unknown` when one of these holds: a global option `--git-dir`, `--work-tree` or `--namespace` is present, in either form; a word before `git` in the commit's simple command begins with `GIT_` and holds `=`; a simple command earlier in the walk begins with `cd`, `pushd` or `popd`. Otherwise it is `resolved`.
D6. Gate. The module resolves the Git common directory of the base folder with `review_capture.git_common_dir`. No line is written when there is none, or when the folder `<git common dir>/readback/reviews` does not exist. The module creates no folder. A repository without that folder gets no capture and no observation file.
D7. `commit` object. The words after `commit` are parsed from the left. A value is consumed before a further flag is read; a consumed character or word never sets a flag and never counts as a pathspec. Only a standalone `--` that is not a consumed value ends option parsing.
  - `all`: true only for a parsed `-a` in a short cluster or a parsed `--all`.
  - `amend`: a parsed `--amend`. `dry_run`: a parsed `--dry-run`.
  - `message_source`: the kind of the first of these in parse order: `message` for `-m`, `--message`; `file` for `-F`, `--file`; `reuse` for `-C`, `-c`, `--reuse-message`, `--reedit-message`; `fixup` for `--fixup`; `squash` for `--squash`. Without one it is `none`.
  - Values. In a short cluster the letters are read from the left. One of `m`, `F`, `C`, `c`, `t` takes the rest of the cluster as its value, or the next word when the rest is empty. `S` and `u` take the rest of the cluster and never the next word. The long options `--message`, `--file`, `--reuse-message`, `--reedit-message`, `--fixup`, `--squash`, `--author`, `--date`, `--template`, `--cleanup`, `--trailer` and `--pathspec-from-file` take the text after `=`, or the next word when they have no `=`. Every other option takes no word.
  - `pathspecs`: the number of words after the ending `--`, plus the number of words before it that are neither an option nor a value; `null` when `--pathspec-from-file` is parsed.
D8. Line. One JSON object with exactly these keys: `schema_version` (2), `parse` (D3), `time` (UTC, `YYYY-MM-DDTHH:MM:SSZ`), `sub_agent` (true when the event's `agent_type` is a non-empty string, else false), `commit_count`, `commit` (null for `parse` `failed`, otherwise D7), `target` (`unknown` for `parse` `failed`, otherwise D5), `capture`, `reviews`, `reviews_state`, `unmatched_markers`, `elapsed_ms` (after the capture and review outcomes are fixed, the module reads the monotonic clock once, immediately before it serializes the line and before it opens the file; `elapsed_ms = int((sample - budget_start) * 1000)`; serialization, opening and writing are not in it), `eligibility` (the string `UNVERIFIED`).
  - `target` `resolved`: `capture` is `{"state", "reason", "manifest_sha256", "index_sha256"}` of `review_capture.capture(base, <remaining budget>)`.
  - `target` `unknown`: no capture is taken; `capture` is null, `reviews` is null, `reviews_state` is `no-identity`, `unmatched_markers` is null. The line goes to the repository of the base folder; that is the place of storage, not a statement about the commit's target.
D9. Reviews, only for a capture with state `ok`.
  - Marker. A name of 32 lower-case hex characters in `<git common dir>/readback/by-manifest/<manifest_sha256>/`. Any other name there is ignored. An absent marker folder gives `reviews` `[]`, `unmatched_markers` 0 and `reviews_state` `ok`.
  - Record. For each marker the module looks for `<git common dir>/readback/reviews/<key>/<marker>.completed.json` in the key folders. A `FileNotFoundError` from the first `lstat` of a candidate means that no record is at that path; the search goes on in the other key folders. A candidate that is not a regular file is invalid. A record is valid when `lstat` shows a regular file and it parses as a JSON object whose `schema_version` is the integer 1 (a boolean and a non-integer number are rejected) and whose `attempt_id` equals the marker. A file with invalid JSON, another schema version or another `attempt_id` is invalid. Any other `lstat` error, and any I/O error after an `lstat` that showed a regular file, makes the lookup `error`, with `reviews` and `unmatched_markers` null.
  - Entry. Each valid record gives `{"attempt_id", "review_key" (the folder name), "created", "verdict" (its `judge.verdict`), "binding", "contract_sha256" (its `contract.sha256`), "handoff_sha256" (its `handoff.sha256`)}`. A value that is not a string, or whose container is missing or is not an object, is null.
  - `reviews` is the list of entries sorted by `(created or "", attempt_id, review_key)`. `unmatched_markers` is the number of markers without a valid record.
  - `reviews_state`: `ok`; `no-identity` when the capture is not `ok` (`reviews` and `unmatched_markers` null); `timeout` when the budget ended during or right after the lookup (both null); `error` when the lookup raised an ordinary exception (both null).
D10. Budget. 5 seconds on a monotonic clock, started before the common directory is resolved. The module reads the clock at these boundaries: (a) before the capture; (b) before each marker; (c) before each record read; (d) after the lookup. At (a) with no time left, no capture is taken and `capture` is `{"state": "timeout", "reason": "budget ended before the capture", "manifest_sha256": null, "index_sha256": null}`. At (b), (c) or (d) with no time left, the partial lookup result is discarded and `reviews_state` is `timeout`. Otherwise the capture gets the time that remains.
  Precedence. A failed gate (D6) comes first and writes nothing. An unknown target keeps the null fields of D8, with no capture and no clock reading at a boundary. Boundary (a) applies only to a resolved target. Boundaries (b), (c) and (d) apply only after a capture with state `ok`. An absent marker folder gives an empty lookup result that still passes boundary (d). An ordinary exception in the lookup gives `error`, and boundary (d) is not read; otherwise no time left at (b), (c) or (d) gives `timeout`. Both discard the partial reviews and set `unmatched_markers` to null.
D11. Write. The line is the JSON text with sorted keys, separators `,` and `:`, ASCII only, and one line feed at the end. The path is `<git common dir>/readback/commit-observations.jsonl`. The module first tries an exclusive creation: `os.open` with `O_WRONLY | O_APPEND | O_CREAT | O_EXCL | O_NOFOLLOW` and mode `0o600`, then `os.fchmod(fd, 0o600)` before the write. If `fchmod` raises, the module closes the descriptor and appends no byte; the new empty file stays with its creation mode, `0o600 & ~umask`. When the file exists it opens it with `O_WRONLY | O_APPEND | O_NOFOLLOW` and leaves its mode. It makes one `os.write` call. It never truncates, replaces or rolls back.
D12. Faults and what persists. (a) A module cannot be imported, the capture module included: no new byte. (b) The capture raises an ordinary exception: one line with `capture` `{"state": "error", "reason": "capture raised", "manifest_sha256": null, "index_sha256": null}` and `reviews_state` `no-identity`. (c) The capture returns unsupported, timeout or error: one line with that capture and `reviews_state` `no-identity`. (d) The budget ends: one line as D10 states for that boundary. (e) The lookup raises, or a record read fails with an I/O error: one line with `reviews_state` `error`. (f) The open fails, the folder cannot be written, or the write fails before a byte is written: no new byte. (g) The write returns a positive short count: that prefix of the line stays, and nothing else is written. (h) `fchmod` fails on a new file: the empty file stays with mode `0o600 & ~umask`, and no byte is appended. In every case the hook prints nothing and exits as the hook at `2929b899585092be2da505cd739d272336d919bb` does. `KeyboardInterrupt` is not caught.
D13. No argument values. The module copies no argument value of the command line into a field of the line. StoreTests gives the message, a path, the author, the date, a revision and an option value distinct sentinel texts and asserts that the file's bytes hold none of them.
D14. Layouts and bytecode. The guard looks for the modules in its own folder first (the portable skill: `readback/scripts/`), then in the folder `scripts` beside its own folder (the plugin: `hooks/` and `scripts/`). It sets `sys.dont_write_bytecode = True` before it imports them. `scripts/sync.py` lists `commit_observation.py` for the portable skill.
