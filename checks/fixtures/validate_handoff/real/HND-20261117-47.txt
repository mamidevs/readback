How FaultTests injects (disclosure): every fault run, the control included, starts `python3 -B wrapper.py <hook>`. The wrapper puts the layout folders at the front of sys.path, pre-imports review_capture and commit_observation, replaces module-level names (_clock, _now, _lstat, _open_file, _os_open, _fchmod, _write) and review_capture.capture, then runs the hook with runpy. So FaultTests uses a fake capture, a scripted clock and a fixed time. The hook's own sys.path and bytecode lines are exercised only by HookTests (a real process, no -B, the real capture). The import faults run the hook directly, without the wrapper.

Choices that the contract does not pin (each is asserted by a named test)
1. The hook holds two new functions, simple_commands and holds_commit. D1 forbids importing commit_observation on a line without a commit call, so the exact D3 test must run in the hook before any import. Two copies of D3 exist (hook and module); test_the_hook_predicate_and_the_module_agree and test_the_option_sets_are_the_same compare them. If "one function" was strict, tell me where the D3 test should live.
2. Boundary (c) is read per candidate whose lstat shows a regular file, just before the open. A candidate that does not exist gets no (c) read. The other reading (before each lstat) changes only the read counts; test_the_budget_ends_at_each_boundary pins mine.
3. Walk order: all $( ) substitutions of a text left to right, then the backtick pairs, each innermost first, then the text itself; at each level the substitution body is removed and its delimiters stay as the word `$`. So `git commit -m B; echo $(git commit -a)` describes the substitution (X-substitution-first-in-walk-order).
4. eval and shell -c: the outer simple command is cut after `eval`, or loses its -c string, and the walked commands follow it. So `eval git commit` counts once (C42), words before `eval` or the shell are not carried into the walked commands.
5. A commit call is per simple command (first qualifying git word); count is per simple command (X-one-per-command). Empty simple commands are dropped.
