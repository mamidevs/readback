## Gap

On 2026-11-19 five worker prompts named a contract id and carried no statement. The workers wrote "no ACC ids". The lead had no rule that a prompt holds the contract, and nothing checked it.

## Change

| Piece | Change |
|---|---|
| `output-styles/readback.md` section CONTRACT and PROTOCOL.md section 3.2 | Three sentences: the complete contract goes in the worker's prompt or as the path of its record; the complete contract holds its statements, their checks and the out-of-scope line; a contract id alone delivers no statement. |
| `agents/worker.md` section Before you start | A worker that cannot read the statements of a named contract returns UNABLE, names the contract and changes no file. The line for a task without a contract stays. |
| `hooks/guard_dispatch.py` | At PreToolUse for the tool Agent or Task with the sub-agent type readback:worker, the hook denies a prompt that names a CON id and delivers it neither by a record path ending with `<id>.md` nor by a statement line. |
| `hooks/hooks.json` | Registers the hook with the matcher `Agent|Task`. |
| `portable/skills/` | Regenerated by `scripts/sync.py` from the texts. The hook is not copied. |
| `INSTALL.md` | States that the hook runs in Claude Code only and that a Codex lead has the two text rules only. |

## Limits

- The hook reads the prompt only. It does not show that the worker read the contract.
- A statement line is a line with ACC-<n> at its start and at least three more words; the hook does not judge whether the statement is right.
- An absolute or `~` path must name an existing file; a relative path is accepted without a check.
- The hook does not run in Codex. A Codex lead has the two text rules only.
- The hook fails open: any error gives exit status 0 and empty output.
